# PWR engineering audit — 2026-09-25

Scope: read-only inspection of this checkout and the three local model folders under `~/.pwr/models`; only this document was created. “Verified” below means established by the cited code, artifact, test, or dated run record. It does **not** mean a fresh live-model run was performed. Dated experiment reports are observations of their stated binaries and conditions, not proof of the present release. Paths and line numbers refer to this checkout on 2026-09-25.

## Executive summary

PWR has a real shipped desktop path: Angular → Tauri bridge → `pwr serve --stdio` → conversation loop → provider → MLX sidecar. It has bounded per-generation tokens, a Qwen delimiter budget, one forced close, one finalization retry, a contiguous-output repetition guard, cancellation, and action-level stall/refusal detectors. These are substantive mechanisms, yet they do not establish reliable termination or complete answers across models. In particular, the sidecar's fallback sampler is greedy (`temperature=0`, `top_p=0`, `top_k=0`); it does not load `generation_config.json`. Packaged profiles normally cover listed exact model references, but Provisional or mismatched artifacts inherit that fallback. Local Qwen3.6 and Qwen3.8 `generation_config.json` files both say temperature 1.0, top-p .95, top-k 20. An earlier real workspace run without a loaded profile observed greedy Qwen3.6, long reasoning, repetition stops and edit cycles; the packaged-profile fallback fixed *that loading defect*, not the unprofiled path (backlog D.E2E-24).

The next release should focus on effective-parameter provenance, generation finish and structure classification, and bounded measurable loop/finalization behavior. Adaptive budget extensions are a research design pending controlled model evidence. Conversation rewind should wait: existing resume, checkpoints and hash-safe Revert provide a base, but deterministic historical workspace restoration needs new snapshots and conflict handling.

## Shipped-path trace

`agent.store.ts:620-644` sends `session/prompt`; Tauri relays JSON lines to `pwr serve --stdio` (`src-tauri/src/lib.rs:242-329`). `serve.rs` locates session, config and conversation; `main.rs:4180-4245` selects MLX deployment, inspects it, uses `pwr_compat::adapter_for(family, ref)`, loads a workspace `strategies/models.json` or compiled-in registry, chooses `ModelProfile::select_for`, assesses compatibility, and resolves `TaskProfile`. `converse.rs:760-827` clones sampling, calculates an envelope from context and prompt estimate, computes a reasoning plan after compaction, overwrites reasoning/max-token fields, and constructs `ModelRequest`. `pwr-mlx/src/lib.rs:744-771` sends only `think`, budget, effort, max tokens, temperature, top-p, top-k and seed to Python. The sidecar renders the artifact's chat template, including `preserve_thinking=True`, optional `enable_thinking`, `thinking_budget`, `reasoning_effort`, and tools; runs `mlx_lm.stream_generate`; tracks explicit think delimiters; and returns deltas/usage/finish. Rust turns non-`stop` finishes into provider faults (`pwr-mlx/src/lib.rs:1000-1045`); on `stop`, it normalizes tool calls via `pwr-compat` before the orchestrator validates and executes them. Actions, verification, generation events and checkpoints flow to local audit/ACP updates. Reasoning streams live but is excluded from conversation history.

A Provisional model is usable if static inspection and applicable local evidence do not bar it (`pwr-models/src/profile.rs`, `main.rs:4205-4221`). With no matching declared profile, `TaskProfile::resolve` yields empty sampling. Template inspection can still enable a conservative reasoning budget; *sampling* still reaches the sidecar absent and becomes its defaults. “Provisional” does not mean unsupported.

## MLX runtime reliability findings

1. **P0 unprofiled sampling mismatch.** On an exact-ref miss, conservative sampling resolves to 0/0/0. Local Qwen3.6 and Qwen3.8 artifacts specify 1.0/.95/20. The 2026-09-22 game run actually saw greedy Qwen3.6 when the profile registry failed to load (backlog D.E2E-24). That specific load path is fixed by compiled profiles, but any Provisional or selector miss still has the same risk.
2. **P0 structural finish ambiguity.** `finish_reason=stop` is accepted before model-specific structural completeness is established (`pwr-mlx/src/lib.rs:1000-1045`). Qwen parser diagnoses unclosed calls (`pwr-compat/src/lib.rs:206-250`) and the orchestrator validates decoded actions; this reduces execution risk but does not provide one generic “complete final / incomplete structured / interrupted” result. A natural-language fragment ending at EOS cannot be proven semantically complete.
3. **P0 budget policy can interrupt productive work.** Fixed Low/Medium/High thresholds trigger a forced delimiter after N tokens, without a progress test (`pwr_mlx.py:704-725`). The remaining cap allows an answer, and one retry is bounded, but no evidence says a productive model will finish before its threshold. The mechanism is a safety bound, not an adaptive strategy.
4. **P1 repetition guard exists but is narrow.** It tests the entire decoded suffix every 32 tokens for four contiguous copies of a passage at least 200 characters (`pwr_mlx.py:89-161,695-703`). It is channel-blind and reports only `repetition`/truncation upstream. It misses noncontiguous repeated thoughts, shorter cycles, paraphrase loops and tool plans. A prior broader rule falsely stopped legitimate code, so thresholds need corpus tests.
5. **P1 failure metrics lose detail.** Sidecar returns timing/token counts on `repetition` and `length`, but Rust `terminal_of` turns those into errors before constructing normal `GenerationMetrics`; the conversation records elapsed/streamed counts in `turn.failed`, not all sampler, channel and detector detail. `PWR_MLX_TRACE` can store raw messages/output when explicitly enabled (`pwr_mlx.py:121-139`); it is unsuitable as default private-reasoning observability.
6. **Research wall-clock bound needs verification per request.** Rust uses timed waits (`pwr-mlx/src/lib.rs:286-380`) and chat configuration has timeout values, yet this audit did not run a hung-device experiment. Treat hard duration behavior and cleanup under GPU stall as unproven, despite token/cancel bounds.

## Reasoning-loop root-cause candidates

**Verified:** a prior Qwen3.6 run outside checkout lacked its profile and used greedy fallback, with reasoning on; packaged fallback repaired that route (backlog D.E2E-24; `main.rs:6526-6557`). On the recorded A.17 task, thinking-off runs were faster and correct twice, while thinking-on runs were longer and wrong twice; the sample is too small to generalize. A Qwen3.8 run was later corrected from “reasoning stall” to a different generation/prefill problem (backlog D.E2E sections), so avoid one cause for all long waits. `preserve_thinking=True` corrected a measured Qwen3.6 cache invalidation after user messages (D.E2E-21).

**Hypotheses requiring controlled tests:** profile mismatch on newly downloaded refs; greedy sampling increasing loops; native template/stop-marker mismatch; a model reasoning past useful convergence; context estimates leaving insufficient answer room; forced close injecting a delimiter at an unsafe semantic point; hardware/prefill stall; prompt-cache divergence; a model continuing reasoning after `</think>` in apparent answer text. Each must be isolated by exact artifact, seed, profile, prompt, engine version and trace of finish reasons, without persisting reasoning content.

## Adaptive Reasoning Finalization design

Proposed generic coordinator receives tokenizer events, parser/channel state, context room, elapsed time, token counts and cheap repetition/progress statistics. A model/template adapter declares safe controls: native thinking on/off, native budget/level, explicit close delimiter and whether an in-process continuation is safe. **Initial soft budget → bounded extensions when progress evidence is positive → hard token/time/context ceiling**. The ceiling is never extended. Default unknown signals permit at most a short bounded extension only if safe; unknown is not “progressing.” A converging model may be invited to finalize at a safe delimiter boundary; no arbitrary insertion inside structured output. This is a design for experiments, not a claim that convergence can be inferred perfectly.

| State | Observable signals → transitions | Allowed / forbidden intervention; budget, time, context and failure |
|---|---|---|
| THINKING_PROGRESSING | Delimiter open; novel non-repeating spans; token diversity and new plan/evidence references → CONVERGING, LOW_PROGRESS, FINAL_ANSWER_STARTED | At soft checkpoint permit one measured extension if context/answer reserve/time remain. Never cross hard ceiling. At ceiling request safe finalization or fail `reasoning_ceiling`; never call it complete. |
| THINKING_LOW_PROGRESS | Falling novelty or repeated self-correction without new evidence → PROGRESSING/REPETITIVE/STALLED/CONVERGING | Short observation window; no unlimited extensions. Safe template transition at boundary only. Time ceiling fails or bounded recovery. |
| THINKING_REPETITIVE | Repeated token windows/n-grams/paragraph hashes with increasing confidence → CONVERGING or finalization attempt | Strong evidence may trigger early finalization. Suppress during structured payloads. Record score/span; do not persist text. At ceiling classify `reasoning_loop`. |
| THINKING_STALLED | No token progress for duration, backend wait, or sharply degraded speed → PROGRESSING/UNKNOWN | Cancellation/sidecar health path; do not inject delimiters into hung stream. Time ceiling classifies backend stall, not model loop. |
| THINKING_CONVERGING | Same conclusion restated, final marker imminent, stable high repetition but valid deliberation still possible → FINAL_ANSWER_STARTED or progress | Conservative early finalization only for verified adapter/template and safe boundary. Do not equate token count with convergence. |
| FINAL_ANSWER_STARTED / PROGRESSING | Think closed or final channel begun; text grows → TOOL_CALL_STARTED/FINAL_COMPLETE/STRUCTURALLY_INCOMPLETE | Reasoning budget no longer applies. Keep answer cap/time/context; do not force thinking close again. On interruption classify completeness; bounded recovery only. |
| TOOL_CALL_STARTED | Tool marker/parser frame open → TOOL_CALL_COMPLETE or STRUCTURALLY_INCOMPLETE | **No reasoning-budget interruption.** Continue within hard output envelope; at hard limit fail as incomplete. Never execute partial call. |
| TOOL_CALL_COMPLETE | Closing delimiter + valid JSON/XML/arguments + schema match → next agent action | Execute only after backend stop/complete frame and policy validation; malformed remains protocol fault. |
| FINAL_COMPLETE | EOS/template final end/engine stop and balanced structure | Report COMPLETE or PROBABLY_COMPLETE per evidence. No further generation. |
| STRUCTURALLY_INCOMPLETE | Open JSON/patch/protocol/tool frame at stop/limit | Never treat as executable or successful. One bounded continuation/finalization if safe; else explicit incomplete error. |
| UNKNOWN | Unsupported template/channel, conflicting markers, lost stop reason | Preserve uncertainty. Hard bounds apply; no unsafe forced close; result `UNKNOWN`/failure requiring calibration. |

For every state the hard wall-clock and context guard is global; the answer reserve shrinks the legal reasoning extension space. Generic mechanisms: counters, rolling hashes, finish taxonomy, balanced JSON/XML/patch frame parsers, metrics and recovery budget. Model-specific mechanisms: delimiters, EOS/end markers, native thinking flags, whether `preserve_thinking` is safe, tool grammar and continuation semantics. Semantic similarity is not justified in the first release: it adds latency, deployment dependence and privacy complexity without proven benefit over deterministic signals.

## Token-level loop detection design

Keep the current contiguous 200-character guard as a backstop while introducing an incremental, tokenizer-aware detector. Compute rolling n-gram and repeated token-window counts, hashes of completed paragraphs, repetition density and sliding-window diversity. Let confidence rise only across several checkpoints and decay on novelty; distinguish reasoning from final text and suspend intervention inside a valid unfinished tool/JSON/patch frame. Short repeated syntax, tables and source-code boilerplate require longer spans and stronger evidence than reasoning prose. Initial mode should **observe and log**, then controlled experiments can enable early finalization for certified templates. Event fields: generated/reasoning/answer tokens, repeated span length, repetition score, window diversity, detector version, extension count, trigger, finish reason. Use counts and keyed ephemeral hashes, never persisted private reasoning text. Benchmark false-positive rate on code/table fixtures and false-negative rate on recorded loop shapes before enabling intervention.

## Final-response completeness model

`COMPLETE`: backend normal stop plus explicit template final closure/EOS and all structured frames balanced, with valid tool grammar where present. `PROBABLY_COMPLETE`: normal EOS and no open structured frame, but ordinary prose has no provable semantic endpoint. `INCOMPLETE`: length/time/cancel/connection loss, open call/JSON/patch/protocol frame, or think closed without final. `UNKNOWN`: conflicting or unavailable stop/channel evidence. Record separate `engine_finish_reason`, `model_eos_reason`, `structure_status`, `final_confidence`; do not compress to one boolean. A tool call is executable only in the first category with schema/policy validation; a prose answer can be displayed with “possibly incomplete” status if evidence justifies it, never falsely as verified completion. Existing `terminal_of` maps all non-stop finishes to faults, a useful base, but does not distinguish these states.

## Recovery strategy

One recovery budget per generation chain, shared across mechanisms. Prefer safe continuation from the same MLX cache/decoder state only if the pinned library supports exact, tested continuation with token/accounting continuity; otherwise one dedicated finalization request with explicit context and prior *visible* output, or the existing thinking-off retry. A new request must not silently duplicate previously streamed answer or reconstruct private reasoning from audit. If an open structured frame cannot be resumed exactly, fail it and let the agent request a fresh call; never execute it. Recovery records parent generation, technique, consumed tokens/time, output ownership and terminal classification. The existing one retry (`converse.rs:900-935`) is a bound, but cannot be recursively combined with a new continuation and another retry. Cancellation remains terminal unless the user explicitly resumes.

## Model Runtime Profile V2

1. **Artifact layer:** read safe JSON/template/tokenizer/processor files as data; record digest/revision/quantization and per-field source. `generation_config.json` is an input, with type/range validation, not executable code. Unknown fields stay unknown.
2. **Capability layer:** derive template controls, delimiters, tools/vision, EOS/context and backend support from artifact plus bounded probes. Record confidence and the exact evidence. A string mention alone is a hint, not a successful behavior test.
3. **Vendor layer:** structured authoritative config may provide candidate defaults with provenance; free-text card guidance stays a visible recommendation until deterministic parsing/review. Do not silently override user values.
4. **Empirical layer:** calibrate exact artifact digest/revision + quantization + tokenizer/template + backend/version + hardware class + calibration version. Keep protocol/termination measurements separate from task quality.
5. **User override layer:** explicit user choices win within safety limits and retain `user_override` provenance, never relabeled empirical.

Resolution should produce an immutable **effective-generation receipt** before each request: every parameter's requested value, source, precedence decision, backend-transmitted value, backend-supported/ignored status and observed finish. Reject unknown/unrepresentable values or disclose them; do not claim a `min_p` profile value was applied when the MLX bridge dropped it. Candidate operating points—general reasoning, precise coding, agent/tool use, fast response, non-thinking—can share an artifact but use different sampling and termination objectives. Reasoning Effort controls reasoning strategy; sampling controls token selection. An explicit offline optimizer evaluates a bounded candidate set, first on verified success, then protocol/tool correctness, termination, repetition/recovery, tokens and latency. It never explores during user tasks. Promote only measured winners with exact deployment identity and per-field provenance; do not fill unknowns merely for schema completeness. The existing legacy exact selectors remain a migration fallback with a warning and invalidation tests.

## Qwen-specific findings

Local `lmstudio-community/Qwen3.6-35B-A3B-MLX-4bit` and `Qwen3.8-27B-MLX-4bit` each have `generation_config.json` with temperature 1.0, top-p .95, top-k 20, `do_sample=true`, and EOS IDs `[248046,248044]`. Their tokenizer templates contain `enable_thinking`, `preserve_thinking`, `<think>`, `</think>` and `<tool_call>`. These are **artifact observations**, not live proof every mode works. Qwen3.8's `config.json` repeats sampler values; Qwen3.6's does not. The sidecar always requests `preserve_thinking=True`, uses `enable_thinking` when a policy supplies a switch, and tracks `<think>` delimiters. Packaged Qwen3.6/3.8 exact-ref entries set `think=false`, so **Low/Medium/High has no effect on reasoning for those matched deployments**. On a Provisional Qwen artifact without a matching “off” profile, the levels translate to distinct bounded budgets if template capability is recognized. Native on/off, PWR effort, and sampling are separate axes. `preserve_thinking` stabilizes historical template rendering and cache; it does not prove reasoning continuity across tool results. If transient reasoning state is tested, keep it only in process memory within one live turn, bind it to model/template/cache identity, erase it on cancel/exit, and never add it to audit/history. First test whether it improves tool-result continuation rather than assuming it does. The local Bonsai artifact has no `generation_config.json`; its `tokenizer_config.json` has no template, but its `chat_template.jinja` does and contains Qwen-like thinking/tool markers. No local Qwen3-14B artifact was available for this audit; existing dated Qwen3 tests/experiments are historical evidence only.

## Conversation rewind/branching design

Create an immutable child conversation with parent ID, branch event ID and selected complete action/turn boundary. Branch A reuses the earlier message/evidence prefix while the workspace stays as it is; reconcile current files and tell the model/person about divergence. Branch B optionally restores workspace state from content-addressed snapshots at that boundary. Reuse `conversation.checkpoint`, receipts, `conversation::restore/reconcile`, and `_pwr/revert` hash guard (`conversation.rs:34,115-260,337-510`; `serve.rs:430-480,1400-1451`). Current checkpoints track changed-file hashes and continuity; they are not complete historical file bytes or a full external-state image. Add bounded content snapshots for PWR-owned edits/deletions, a workspace baseline/tree manifest, symlink/path policy, untracked/new-file state, branch metadata, and user-visible conflict records. Before any restore, compare current hashes to expected later-PWR hashes; refuse modified files and require explicit conflict resolution. Preserve the original audit chain and all later events. Commands/services/network effects cannot be undone deterministically; label them as non-restorable. Migrations need old conversations to offer Branch A only where snapshots are absent. This is P2 and **outside the next release** until inference reliability is measured.

## Observability gaps

Already present: generation start/completion events, effort/budget/profile status, prompt/generated and reasoning/answer counts where delimiters permit, durations, tool/verification events, audit log, diagnose, and context usage (`converse.rs:800-840,1510-1645`; `docs/observability.md` later dated notes). Add a local structured generation receipt: profile ID and selector, per-parameter provenance and applied/ignored state, input tokens, token split with unknown preserved, prefill/TTFT/final latency, extension/repetition/finalization/recovery counts, raw engine and EOS finish reasons, context remaining, parser completeness, stall classification, and verifier outcome correlation. Distinguish backend fault, model repetition, context exhaustion and protocol error. Default metrics must retain no private reasoning text; redact paths or hash identifiers in export. `PWR_MLX_TRACE` currently writes raw model text when enabled and should remain an explicit diagnostic mode with retention controls.

## Architecture/engineering gaps

The provider boundary and typed faults are useful; changing them should follow a demonstrated need. Immediate gaps are ownership of parameter resolution (split across profile, orchestrator, Rust bridge and Python), loss of finish/metric detail on error, and duplicated scripted/conversation loop policy. Resource risks include sidecar child lifetime, prompt-cache invalidation and GPU memory pressure; existing code has unload/cache reset and cancellation paths, but hung-device cleanup needs fault injection. Versioned evidence and schema checks exist; a V2 profile migration must preserve old local calibration and mark stale evidence, not overwrite it. Sandboxing remains central; `docs/external-review-2026-09-23.md` verified `SandboxPolicy::Preferred` may run unconfined without an adapter, and conversation approval defaults were broader than the security prose at that review. Recheck current defaults in a focused security pass before changing them. CI lacks desktop npm tests/build and sidecar unit tests; release workflow pins a single old tag and release reproducibility is not measured across independent builders. Documentation has dated historical sections that need labels, not wholesale replacement.

## Recommended first implementation slice

**Implement an effective-generation receipt with artifact-aware Provisional sampling**, without changing reasoning control yet. It comes first because an unprofiled model can currently run at 0/0/0 even when its local artifact supplies different generation settings; the 2026-09-22 Qwen3.6 run demonstrates the same sampler state was materially associated with runaway behavior when its profile was missing. The fix is small enough to review independently and makes later loop experiments interpretable.

Likely changes: safe `generation_config.json` read and validation in `pwr-models`/MLX inspection; one typed precedence resolver in `pwr-domain` or a narrow runtime module; `pwr-cli` selection and `TaskProfile` integration; `pwr-mlx` request serialization; sidecar effective sampler receipt; local audit event. No model-name heuristics. Keep exact packaged profiles working and explicit user overrides above artifact defaults. Unknown/unsupported parameters stay unknown/ignored with provenance. The receipt should state value, source, resolved priority, transmitted value, applied status, artifact digest, backend/version and profile selector. Do not store prompts or private reasoning.

Tests: absent/exact/digest/workspace override, invalid/missing config, unsupported penalties, Qwen artifact values, full ACP→captured-sidecar request, and no profile present. Live validation: repeat a fixed short and loop-prone prompt with Qwen3.6/3.8 under pinned artifact/seed/hardware, compare current baseline to new resolver for correctness, termination, repetition, tokens and latency. Rollback: feature-gate artifact sampling and restore old resolver while retaining the receipt; any status that reports an applied value must reflect what the sidecar actually used. Regression risks: output variability, benchmark comparability, profile conflicts, vendor config for a different operating mode, cache behavior. **Done** when no supported parameter silently falls back to greedy on an unprofiled artifact that declares it, every generated request has an auditable effective-parameter receipt, old exact profiles retain their behavior, all deterministic gates pass, and controlled live runs show no new completion/tool-call failures. Stop here before adaptive finalization changes.
