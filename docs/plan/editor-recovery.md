# Editor draft recovery

Unsaved text buffers receive private local recovery copies, isolated by canonical trusted workspace. Recovery opens the draft in the editor; it never writes the workspace file automatically. The saved base and original hash remain attached to the recovered text, so the normal checked save rejects an intervening disk change.

The main-window native commands require workspace trust. The private app-data directory has Unix mode 0700 and records have mode 0600. Records are capped at 16 MiB and 64 dirty documents per workspace. A record is written through a unique exclusive temporary file, synced, then renamed; malformed, oversized, linked or mismatched records fail visibly and are retained. Recovery data is local text, not encrypted storage. Standard operating-system account and disk protection apply. No record contents are sent to a server.

The interface waits for the initial recovery read before opening a file. A delayed read is merged only into its own workspace and cannot replace an already opened buffer. While initial restoration is pending, updater/restart guards treat the draft set as busy and model write guards wait for it. Dirty state is persisted after a 100 ms debounce, immediately when leaving a workspace, and flushed at controlled quit. Consequently, an abrupt termination can lose edits made after the last successful copy, including that debounce window. Unreadable copies are preserved when quitting or explicitly discarding; new recovery writes remain blocked with a visible error until the record is addressed. A corrupt record does not trap an otherwise clean app at quit. Disk failures remain visible; this mechanism is not a power-loss or backup guarantee.

Explicit discard removes the corresponding recovery copies before quitting. Confirmation is bound to workspace, path, text, save base and hash; a metadata-only conflict refresh does not invalidate it. A newer edit cancels the quit and restores recovery copies, including hidden workspaces. A native close failure resumes copying. Queued callbacks do not rewrite discarded records while closing.

Automatic regressions cover restore/save-hash preservation, delayed cross-workspace reads, rapid switching, edited confirmation dialogs, hidden-buffer recovery after an interrupted discard, failed record clearing and metadata-only conflict refreshes. Native tests cover private-file round trips, explicit clearing, cross-workspace mismatch, corruption, traversal and symlink refusal. macOS native crash/restart observations and any failed first attempts are recorded in the [verification campaign](../reviews/2026-10-18-product-verification.md). Windows, full disk exhaustion, sudden power loss and arbitrary hostile mutation by the same local account remain outside these scoped results.
