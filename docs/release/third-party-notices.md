# Bundled third-party attribution material

The native build assembles `Contents/Resources/notices` with PWR's license, Angular's generated frontend attribution file, the bundled font license texts, available license texts from Cargo packages, and uv's own license files. Previously, the Angular file was generated outside `frontendDist` and neither that file nor uv's licenses reached the native bundle.

`node scripts/bundle-notices.mjs` runs after frontend/core/uv preparation. It traverses the locked Cargo graphs for the actual host target (or `CARGO_BUILD_TARGET`), excludes development edges and conservatively retains build dependencies. This is a source-package attribution inventory, not proof that every listed package is linked into the executable. Explicit cross builds must set the target consistently. Windows execution and package qualification remain in the final Windows phase.

The generated inventory records package names, versions, license declarations, source references, available text paths and SHA-256 hashes. It does not contain local Cargo source paths. Required PWR/frontend/font/uv inputs fail the build if missing. Inputs are collected before replacing the prior generated set, so a collection failure retains the last complete output. The tracked README remains available for development builds; generated files stay ignored by Git.

The generator does not invent missing copyright or license texts, reinterpret license expressions, fetch an unpinned latest license, or mark the result legally cleared. The current Apple-silicon graph contains 426 package records and 712 attribution texts, with 23 explicit review items: 22 package records lacking packaged text and uv's unresolved transitive binary attribution. Several missing files belong to build dependencies or monorepos that describe licensing at their root; those facts do not remove the recorded review requirement. Managed Python distributions and downloaded model weights are separate inventories.

`python3 scripts/verify-notices.py PATH --target aarch64-apple-darwin --uv UV_PATH` verifies every text hash and size, exact file membership, safe paths, matching target and the uv executable hash. It rejects missing/changed texts, traversal, symlinks, duplicates and extra files. The macOS release script runs it against the app mounted from the produced DMG. Its output always retains `legal_clearance: false`; the unresolved count is a review list, not a release waiver.

Local qualification: repeated generation yields the same inventory hash; a deliberately missing Angular input fails while preserving the prior set; all text hashes match. Five verifier regressions pass. The unsigned macOS app rebuilds with the actual notices directory (about 5.4 MiB), and the verifier passes on that bundle. The 12 native tests pass after the resource configuration change. This closes the scoped missing-bundle-material defect, not all distribution licensing or release gates.
