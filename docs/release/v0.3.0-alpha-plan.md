# v0.3.0-alpha plan — consolidation and Windows

Decided by the maintainer on 2026-09-28, after v0.2.0-alpha was published.

**The idea.** v0.3.0-alpha adds one thing, the Windows engine, and otherwise
makes what already exists solid. No new features enter until 0.3 ships. The
work between 0.2 and 0.3 is testing, stress testing and fixing: understanding
where the current architecture is fragile and making it stable. New features
are chosen after 0.3, on top of a base that has been measured.

## Before 0.3: v0.2.x fixes on macOS

Problems found in v0.2.0-alpha ship as v0.2.x patch releases, as v0.1.1 and
v0.1.2 did, so Mac users are not left waiting for 0.3.

1. **Models that do not work in agent mode.** Some models chat correctly but
   fail as agents. For each one, record the model, quantization, size and the
   failure: no tool calls, malformed tool calls, loops, stopping early or
   ignoring the result of a tool. Reproduce it on a fixed small task, then
   decide whether the harness can fix it (chat template, tool-call parsing,
   sampling, prompt) or the Model Manager must say that the model is not
   suitable for agent mode.
2. **Graphical bugs in the desktop app.** Collect them from the manual walk
   of the 0.2 DMG: Focus, resizable cards, the three trace views, themes in
   light and dark, narrow windows and full screen. Fix them with a screenshot
   before and after.
3. **.NET installed per user.** The sandbox does not read `~/.dotnet`, where
   Microsoft's install script puts .NET, so `dotnet` exits 131 inside it.
   Fix the sandbox and remove the CI-only skip from
   `dotnet_runs_in_the_sandbox_on_its_first_run`.
4. **`look_at` on GitHub's runners.** The headless browser writes no
   screenshot inside the sandbox there, while it does on a developer Mac.
   Find the cause and remove the CI-only skip from
   `look_at_photographs_a_workspace_page_from_inside_the_sandbox`.
5. Anything else the manual walk of the 0.2 DMG turns up.

## v0.3.0-alpha

### Windows engine

- llama.cpp kept alive across turns (R.4) before any GGUF performance claim.
- Command isolation on Windows: macOS's seatbelt has no Windows counterpart,
  so the permission model must hold there by other means.
- A Windows installer, and the main flows at parity with the Mac: engine
  setup, model download, chat, agent, goal mode, permissions.

### Consolidation through tests

- **Agent-mode model matrix.** The models the Model Manager offers, run in
  agent mode on the same fixed tasks, with a recorded result per model. The
  Model Manager states which models are suited to agent mode.
- **Stress tests.** Long sessions and many turns through compaction; large
  repositories; background work (wiki summaries) during a turn; cancel,
  rewind and resume; the app or the engine killed mid-turn; low memory and
  models near the machine's limit; the network off; long-running commands
  and services.
- **Repeated campaigns.** Several runs per task (pass@k) on the pinned
  corpus, so a change is judged on more than one run.
- **Architecture review.** From the stress results, name the weak points and
  consolidate them; the scripted runner and the conversation runtime still
  differ in planning, compaction and recovery.

### Release gate

- CI green on macOS and Windows, with no CI-only skips left.
- The stress suite passes on both platforms, with its thresholds written down
  before the run.
- The main flows walked by hand on the built Mac and Windows apps.
- The agent-mode model matrix is published with the release.
- Known limits listed in the release notes.

## After 0.3

Candidate features, to be chosen once 0.3 is stable: evidence recovery after
compaction and long-task context (C.22b), versioned documentation RAG
(C.22c), the MoE expert-routing experiment, speculative decoding and the
public evidence site.
