# PWR v0.1.0-alpha — technical readiness

**Assessed 2026-09-24**, on the `redefinition` working tree, before packaging.
Target: macOS on Apple silicon only. Windows and Linux are out of scope for
this alpha. This is the technical core's readiness; packaging (DMG, signing,
notarization, clean-install QA) is the next task and is not assessed as done
here.

Every "ready" below names its evidence. Where the evidence is a fake-model
test rather than a real model, it says so.

## READY

**Unknown models are usable, not refused.** A model with no pwr profile is
*Provisional* and runs with conservative defaults; only concrete evidence
(unreadable artifact, an MLX model with no chat template, no reply at all)
makes it *Incompatible*.
Evidence: `crates/pwr-models/tests/compatibility.rs`
(`an_unknown_model_is_provisional_and_usable_not_unsupported`,
`a_model_without_a_chat_template_is_incompatible_before_anything_runs`);
live: `Qwen/Qwen3-14B-MLX-4bit`, which has no profile, was assessed
Provisional before calibration.

**Quick Calibration.** Nine fixed requests, scored mechanically (exact match,
JSON parse, JSON-Schema validation of tool arguments, a fixed tool-result
transcript), temperature 0, fixed seed, 120 s per request, cancellable
mid-generation, nothing recorded when cancelled; a timed-out request fails its
check and the run continues. Outcomes: Locally calibrated / Limited /
Incompatible.
Evidence: 17 tests in `crates/pwr-models` (fake models: capable, no tool
calls, ignores tool results, generates nothing, forced close fails, hangs,
cancelled before and during a request); **live**: Qwen3-14B 4-bit on this
host (M2 Max, 64 GB) → Locally calibrated in 21 s, 9/9 checks, an answer
followed the engine's forced close at a 16-token thinking budget.

**Limited mode.** A model that fails an agent-critical check keeps chat
without a workspace; agent tasks in a workspace are refused with the reason
and suggestions. Evidence: `a_model_that_cannot_call_tools_is_limited_and_keeps_chat`,
`a_model_that_ignores_tool_results_is_limited`; the gate in `chat_turn`
(`crates/pwr-cli/src/main.rs`); UI rendering checked in the browser pane
(demo mode).

**Provenance and reuse rules.** Evidence is tied to artifact digest, weight
files, quantization, revision, tokenizer, chat template, backend and engine
version, suite version and hardware class; fixed rules decide reuse /
reduced confidence / stale. Local evidence lives in `~/.pwr/model-evidence`,
never in a repository. Evidence: `compatibility.rs`
(`a_changed_quantization_or_template_makes_the_calibration_stale`,
`a_backend_update_lowers_confidence_and_a_major_one_voids_it`,
`harmless_changes_do_not_invalidate`,
`verified_evidence_applies_only_to_its_artifact_and_a_local_failure_outranks_it`,
`evidence_is_stored_outside_the_repository_and_read_back_by_key`); the MLX
engine now reports its version (`mlx-lm`, `mlx`, engine-script hash) --
before this it reported none.

**Reasoning Effort (Low / Medium / High, Medium default).** A typed enum end
to end; a per-generation thinking budget computed after compaction, clamped to
the context with a guaranteed answer reserve (4,096 tokens, or all the room if
less). LOW < MEDIUM < HIGH for every mapping.
Evidence: `crates/pwr-domain/tests/reasoning_effort.rs` (12 tests including
a property test: budget ≤ requested, generation ≤ room, answer reserve kept,
input + generation ≤ window); turn-level tests in
`crates/pwr-cli/src/two_loops.rs` (each effort sends its own budget; High
clamped in a 12K window; no budget for an unknown capability);
**live** (Qwen3-14B, calibrated mapping): Low → budget 2,048, the engine
counted exactly 2,048 thinking tokens, closed the phase, and the model
answered; Medium (6,144) and High (12,288) → the model finished thinking by
itself at 2,554 tokens, no truncation.

**Reaching the budget does not destroy the reply.** The MLX engine closes the
phase with the template's own delimiter, once, and lets the answer follow in
the reserve; a reopened or empty answer ends `reasoning_unfinished`, the turn
retries once with thinking off, and a second failure stops the turn with a
stated reason. It cannot loop.
Evidence: sidecar tests (`crates/pwr-mlx/sidecar/test_pwr_mlx.py`, 22
tests: close-and-answer, reopen fails once, no answer fails, the backstop
reserve, cancellation inside reasoning); `two_loops.rs`
(`reasoning_that_ends_without_an_answer_is_retried_once_with_thinking_off`,
`reasoning_enforcement_cannot_loop`,
`a_tool_call_after_a_closed_budget_runs_and_the_audit_holds_counts_not_reasoning`);
live Low run above.

**Honest degradation.** Models whose reasoning cannot be bounded (harmony /
gpt-oss: level only; llama.cpp: observable only; unknown or none; profile
turns thinking off; forced close failed in calibration) get no invented
budget, and the selector is disabled or explained.
Evidence: `models_without_a_controllable_phase_are_not_given_a_budget`,
`a_template_that_takes_levels_gets_the_level_and_no_invented_budget`,
`a_profile_that_turns_thinking_off_is_respected_at_every_level`,
`a_forced_close_with_no_answer_disables_the_budget_rather_than_pretending`;
frontend `compatibility.spec.ts`.

**Audit without chain-of-thought.** `generation.started`,
`reasoning.started`, `reasoning.budget_reached`, `generation.finalizing`,
`reasoning.completed`, `reasoning.finalization_failed`,
`generation.completed` carry counts, budgets, clamping and accounting source;
a test asserts no event contains the reasoning text.

**Context and compaction unchanged in behaviour.** All existing compaction
tests pass (see the quality gate); reasoning is never written back into the
history, and the budget is recomputed after each compaction.

## PARTIALLY READY

- **Token accounting.** Exact on MLX (the engine counts with the loaded
  model's tokenizer; reasoning vs answer split exact for templates with
  tracked delimiters). On harmony models the split is unknown (reported as
  unknown, not zero). On llama.cpp the split is known only if the server
  reports it. Tool-call tokens are an estimate (labelled). Context
  composition remains characters ÷ 4 (labelled).
- **Backend limitations.** Budget enforcement exists only on the MLX engine
  for `<think>`/`<seed:think>` templates. gpt-oss gets the level through its
  template, not a budget. llama.cpp cannot be bounded per request and is
  itself a slow path (server started per generation, backlog B.7/R.4).
- **Verified profiles.** The mechanism, registry and rules exist and are
  tested; **the registry is empty.** Every model starts Provisional until
  calibrated on the user's machine. Earlier evaluations were not converted:
  they lack artifact provenance and ran on older engine builds.
- **Packaged model profiles** (`strategies/models.json`) still match by model
  reference, not artifact digest. They set sampling and turn thinking off;
  they no longer imply verification.
- **Model Manager.** Implemented (Hub search via JSON API, fit rating,
  verified resumable downloads, local list/delete); downloads now record the
  Hub revision. Not re-exercised end to end in this pass.
- **Calibrated budgets for the catalogue models.** Five of the six catalogue
  models on this host have profiles that turn thinking off, so the effort
  control is disabled for them by design. gpt-oss is the exception: it cannot
  switch reasoning off, so its native low / medium / high levels apply
  (default Medium; its profile previously pinned it to `low`). No calibrated
  token budget exists for any of them.
- **Hardware detection.** Implemented and unit-tested; the hardware class used
  for provenance is coarse by design.

## BLOCKING (for packaging, not for the technical core)

These do not block the runtime behaviour assessed above, but a DMG cannot
ship a working app until they are solved:

1. **The MLX engine is not bundled.** The sidecar script's default path is
   the build machine's source tree (`CARGO_MANIFEST_DIR`), and the Python
   environment with `mlx-lm` is created by `scripts/setup-mlx.sh` in the
   checkout. A packaged app needs the script as a bundle resource and a
   defined way to provide the Python environment.
2. **The core binary is not bundled.** The Tauri shell finds `pwr` via
   `PWR_CORE`, the checkout's release build, or `PATH`
   (`apps/desktop/src-tauri/src/lib.rs`); no `externalBin` is configured.
3. **Webview CSP is disabled** (`"csp": null` in `tauri.conf.json`); set one
   before distribution.
4. **Revert bypasses the core.** "Revert" in the app writes workspace files
   directly from the Tauri shell (`restore_workspace_file`), outside the
   core's audit and without checking that the file still holds the model's
   version -- a later manual edit would be overwritten. Filed as a separate
   task; should be fixed before a public build.

## MANUAL TEST REQUIRED

Automated tests cover the logic; these need a person in the real app on a
clean Mac:

- Model Manager: search, download, cancel/resume, verify, delete; a model
  downloaded by the app then calibrated.
- Unknown-model flow in the app: "New model detected" → Run Quick Calibration
  (progress lines, Cancel) → Locally calibrated / Limited result lines; "Use
  Conservative Defaults" remembered across restarts.
- Reasoning Effort in real turns on a thinking-enabled model: the selector,
  the "Last reply" line in the Context panel, a turn whose budget closes and
  still makes a tool call.
- Context panel: manual Compact, automatic compaction in a long task.
- Repository opening, agent task execution, edits, diffs, Revert (see
  blocking item 4), deterministic verification (the repository's own checks).
- Error handling: engine missing (no `mlx-lm`), model folder removed while
  selected, a calibration of a model that fails to load.
- Cancellation: Stop during a long reasoning phase (the engine stops within a
  token -- sidecar-tested), Cancel during calibration.
- Persistence: workspace settings (effort, window, acknowledged models),
  conversations resumed after restart, calibration evidence surviving an app
  update.
- Offline: the engine never contacts the Hub (`HF_HUB_OFFLINE=1`); the Model
  Manager's Hub-unreachable state.
- A second live calibration per template family: Seed-OSS (native budget) and
  Qwen3.6/3.8 with thinking enabled.

The opt-in live test repeats the measurements above on any local model:

```bash
PWR_MLX_PYTHON=$PWD/.venv-mlx/bin/python PWR_LIVE_MODEL=Qwen/Qwen3-14B-MLX-4bit cargo test -p pwr-models --test live_model -- --ignored --nocapture
```

**Regression found and fixed during the gate:** `conversation::latest`
(what `--continue` resumes) had been changed by earlier uncommitted work to
"most recent event of any kind"; the existing test
`the_latest_conversation_is_the_one_that_last_finished_a_turn` caught it. It
is again "the last conversation that finished a turn", skipping deleted ones.

**Stale test fixed:** the sidecar's `StableHistory` test (runs only with
Qwen3.6 on disk) still expected `render` to return tokens alone, which has not
been true since the vision change (C.25).

## Is the technical core ready for the packaging phase?

**Yes, for the runtime and model behaviour assessed here, with the caveats
above.** The unknown-model path, Quick Calibration, provenance rules and
Reasoning Effort are implemented, tested with fakes at every layer, and
confirmed live on two models with different reasoning mechanisms; the full
gate is green and both release builds succeed.

**Not yet ready to ship as a DMG**: the four BLOCKING items (engine and core
not bundled, CSP off, Revert outside the core) are packaging-phase work and
must be closed there, and the MANUAL TEST list must be walked on a clean Mac
before a public build. Nothing in this pass has been exercised by a person in
the packaged app.
