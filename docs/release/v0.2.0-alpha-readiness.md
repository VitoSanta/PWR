# v0.2.0-alpha release readiness — source audit, 2026-09-28

> **Status at tagging, 2026-09-28.** On the tagged commit the desktop build
> and tests, `cargo fmt --check`, Clippy with `-D warnings`, the Rust test
> suite and the milestone manifest check pass locally. The DMG is built and
> checked by the tag workflow. The manual walk-through in gate 3 is still the
> release owner's.

**Verdict: not ready to tag or publish yet.** This is a static audit of the
`develop` checkout after `babe2776`, compared with `v0.1.2-alpha`. It does not
start PWR, run a model, build a DMG or run tests. The completed reduced c4
run's nine result metadata files were read without opening held-out task files.
Source presence means a reachable implementation exists;
it does not prove the release artifact works end to end.

## Repository and packaging audit

- Version strings have been prepared as `0.2.0-alpha` in the workspace and
  Tauri manifests, both Cargo locks, npm manifest and lock, Tauri config and
  release script. The tag workflow targets `v0.2.0-alpha` and the draft notes;
  CI is configured for pushes to `develop`, `stage` and `main`, plus PRs.
- The 26 byte-identical screenshots in `docs/product-screenshots/15-other/`
  were removed; the categorized originals remain. The lone `c.jpg` original
  was identified as the engine-install progress capture and renamed to match
  the link in the screenshot index. Generated `target/`,
  `dist/`, `node_modules/`, `.pwr-scratch/`, Python bytecode and local `tmp/`
  are ignored, not tracked. The old ignored DMG in `dist/release/` is a
  v0.1.2-era artifact and is not evidence for this release.
- Local brand changes are in progress: icon files and favicon are modified,
  old PNG marks are deleted, and the replacement SVG and Angular component
  are untracked. This audit did not overwrite or finalize them. They must be
  reviewed together and included in the release candidate.
- The screenshots in `docs/product-screenshots/` are dated captures of the
  earlier app. They are historical product evidence, not screenshots of Focus.
- The backlog's R.6 third-party licence inventory is still open; no generated
  inventory was found in the tracked release files. This audit makes no legal
  compliance determination, but the release owner should close or explicitly
  defer that item before publishing.

## Remaining release gates

1. Finish and review the brand asset change, then ensure the intended SVG,
   Angular component, favicon and Tauri icons are all included in the commit.
2. Obtain a clean, reviewed release candidate and run the CI gates for that
   exact commit: desktop tests/build, sidecar tests, Rust formatting, Clippy,
   Rust tests and the milestone manifest check. No result is claimed here.
3. Walk the built app's main flows by hand on the release candidate: first
   engine setup, model discovery/download, chat, an agent task, goal mode,
   permissions, Focus cards and narrow/full-screen windows. Confirm the new
   brand on both light and dark themes.
4. Run `scripts/release-macos.sh` after the campaign no longer needs the
   checkout's build outputs. The script cleans Rust outputs, builds the DMG,
   verifies its app, signature and checksum. Its result has not been produced
   for v0.2.0-alpha.
5. Keep campaign claims scoped to their records. The earlier 19-to-22 result
   is within this development cycle; reduced c4 passed 7/9 overall and 5/6
   held out. Both use one run per task. Neither is a direct comparison with
   v0.1.2-alpha, a score for all 37 tasks, or a test of the later Focus UI.
6. Resolve the R.6 licence-inventory decision recorded above.
7. After these checks, advance the reviewed commit through the intended
   `develop` → `stage` → `main` release flow and create the version tag. The
   tag workflow makes a **draft** prerelease; publication remains a separate
   decision.

This audit does not establish notarization, Windows support, a persistent
desktop GGUF engine, a general model-quality ranking or a confirmed uplift
over a fixed baseline. Those are outside this Mac alpha release.
