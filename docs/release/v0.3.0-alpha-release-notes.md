# PWR v0.3.0-alpha

Mac alpha for Apple silicon.

## What changed since v0.2.0-alpha

- **A model can try the page it built.** `look_at` (vision models) and
  `check_page` (text models) take up to twelve steps before looking: a click
  on a button, link, question or list option, text typed into a field, a key
  pressed. The result says what each step did and what the page shows after
  them, and the screenshot appears in the conversation under the action. A
  step that matches nothing lists what the page has. These are DOM
  interactions on a page of this machine; a page that refuses to be framed
  cannot be acted on.
- **Goal mode verifies more of what small models produce.** Checks are found
  below the workspace root in any build system; a pass that ran no test is not
  a pass; a goal with no checks is still read against the request. Verified
  proposals run as a phase of the goal: each proposed edit is kept only when
  the verification verdict improves. The phase is enabled by profile for one
  model and its recorded results are mixed across models.
- **Effects are bounded.** Commands cannot change what the edit tools refuse
  (frozen acceptance files, installed dependencies). A whole-file rewrite is
  checked against the version the conversation last read, writes are atomic,
  and a goal is bounded on every path: actions, refused completions,
  verifications, review rounds and a deadline. Full access remains unconfined
  and says so in every turn's outcome.
- **Three permission modes**: Protected, Standard and Full access. A
  sandboxed command can ask to run once outside the sandbox.
- **Loops are named.** A command that failed the same way twice is not run
  again; five failed runs after edits hand over what is ready; after three
  changes to one file, each followed by a failed run, the result quotes the
  failing lines as the file has them. The last is advisory and its effect on
  a model in that loop has not been measured.
- **More models work.** Adapters for Mistral/Devstral and Liquid LFM2, fixes
  for Qwen3-Coder, Granite 4.1, Gemma 4 and gpt-oss. Sampling is never greedy
  by default. Compaction starts at 75 % of the granted context window.
- **Engine.** MLX 0.32.3 and mlx-vlm 0.7.2. The engine applies the macOS GPU
  context-switch workaround before loading MLX, paces non-fused prefill to
  about a second per chunk, caps MLX's free-buffer cache at 2 GiB
  (`PWR_MLX_CACHE_GB`) and clears it after each generation. This mitigates
  `Impacting Interactivity` failures seen on long goals; it is not a cap on
  total memory, and long-run memory behaviour is unmeasured.
- **Desktop.** Tools are one grid, stacked or side by side, resized by the
  gaps between cards and by one edge for the whole grid; a tool can take the
  window while the top bar stays. The conversation reads as plain actions
  ("Ran npm test"), shows when each message was sent, folds long messages,
  and tells a command that ran and failed from a call that was refused. The
  Files card follows the workspace as it changes; the Web preview follows the
  newest local server; the Terminal holds several shells.

## Evidence and limits

Checked on the commit before the version change (`14f532ae`): the full Rust
suite, 1,585 tests in 107 binaries with none failing and 5 ignored, on the
maintainer's Mac; hosted macOS CI green on its second attempt, the first
having failed one sandbox test (`with_the_grant_a_service_can_bind_and_be_reached`,
a refused loopback bind) that passed unchanged on the re-run.

Comparisons recorded during development are one run per cell and establish no
general success rate. On three small models served by Ollama, nine runs each
on bug-fix tasks: PWR with the proposals phase 96 of 126 acceptance tests,
OpenCode 2.0.20 67 of 126. Manual from-scratch runs, one per side: a .NET CLI
(PWR 13 and 14 of 19 commands, OpenCode 0 of 19 at a 32k context); a Python
CLI (OpenCode 17 of 21; PWR's run was stopped by hand in a repair loop at 2 of
21, before the repeated-repair notice existed); a single interactive page with
Qwen 3.6 35B (PWR 22 of 24 scripted checks; OpenCode could not start because
Ollama 0.40.0's MLX runner fails on that model with a long prompt). See the
[experiment log](../experiment-log.md).

PWR remains an alpha for Apple-silicon Macs. It is ad-hoc signed and not
notarized. Page steps, vision input and the proposals phase are experimental.
Windows, a persistent GGUF desktop path and a unified scripted/conversation
runtime remain outside this release.

## Install

After publication, download `PWR-macOS-arm64.dmg` and `SHA256SUMS.txt` from
this release. In their directory run `shasum -a 256 -c SHA256SUMS.txt`, then
open the DMG and drag PWR to Applications. On first launch macOS may block the
ad-hoc signed app. If you trust the downloaded copy, use **System Settings →
Privacy & Security → Open Anyway** after attempting to open it. Do not disable
Gatekeeper globally.

On first launch PWR installs its private MLX engine; an engine installed by an
earlier version is offered for reinstallation. Download a model from the Model
Manager, then open and trust a workspace. Read
[`SECURITY.md`](../../SECURITY.md) before using an agent on important files.
