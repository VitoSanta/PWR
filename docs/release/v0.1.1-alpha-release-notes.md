# PWR v0.1.1-alpha

Maintenance prerelease for macOS on Apple silicon (arm64).

## Changes

- Keep long MLX tool-call generation alive while its arguments are withheld from the visible reply. The app receives a content-free progress signal rather than mistaking active generation for a silent backend.
- Restart the MLX sidecar if a cancelled reply cannot be drained, so later turns do not wait without a bound.
- Resolve Angular `public/` assets according to `angular.json` in the built-in `pwr:web-assets` check. This removes the false missing-favicon result seen while building the PWR website.
- Read Git status and diffs from a single nested checkout when the selected workspace is its parent, as in the PWR website workspace.
- Explain the common `npx run build` mistake with the correct `npm run build` invocation before executing it.
- Point to the nested project directory when `npm run` is attempted from a workspace that has no root `package.json`.

These changes address the observed failure path in the website run. They do not guarantee that every local model will produce valid tool calls or finish every task.

## Install and verify

Download [PWR-macOS-arm64.dmg](https://github.com/VitoSanta/PWR/releases/download/v0.1.1-alpha/PWR-macOS-arm64.dmg) and [SHA256SUMS.txt](https://github.com/VitoSanta/PWR/releases/download/v0.1.1-alpha/SHA256SUMS.txt). Put both in the same directory and run:

```sh
shasum -a 256 -c SHA256SUMS.txt
```

The output should report `PWR-macOS-arm64.dmg: OK`. Open the DMG and drag PWR to Applications. The app is ad-hoc signed, not notarized by Apple. If macOS blocks the first launch, verify the checksum, then use **System Settings → Privacy & Security → Open Anyway** for PWR. Do not disable Gatekeeper globally.

PWR's first-run setup installs its private MLX engine; a local model must then be downloaded in Model Manager.

## Current limitations

- This desktop release supports macOS on Apple silicon.
- No model currently has PWR's Verified status.
- A local model can still return malformed tool calls or struggle with a long task. Inspect changes and repository checks before relying on its result.

Report reproducible failures in [GitHub Issues](https://github.com/VitoSanta/PWR/issues).
