## What PWR actually is today

A 14-crate Rust workspace with a local CLI/TUI, provider/backend lifecycle contracts, Ollama and LM Studio transports, behavior adapters, calibration and capability probes, an audited workspace tool executor, shallow repository indexing, check discovery/verification, SQLite event persistence, diagnostics and corpus evaluation. It has real engineering safeguards and meaningful regression fixtures, but remains experimental rather than a production autonomous agent.

The historical intent was a calibrated, verified local coding workflow centered on a small installed-model laboratory. Later adaptive-runtime work added portable discovery, profile matching and selection. The latest conversation work improved the user-facing workflow but introduced an independent runtime path. Git commit `f7ad8ca` describes making conversation the loop; code confirms that this did not remove the scripted loop.

## The most consequential mismatch

| Path | Actual behavior | Implication |
|---|---|---|
| Scripted `run` | `run_action_loop_with_prompt_budget_and_context_tiers` in [orchestrator](../../crates/pwr-orchestrator/src/lib.rs) handles measured context, plans, actions, state transitions, baseline/acceptance, recovery and budgets. CLI discovers repository checks. | This is the richest existing foundation for shared execution. |
| `eval` | Uses the orchestrator with corpus-supplied visible verifier, budgets and task-specific scoring. | It cannot establish product check discovery or chat behavior. |
| Interactive conversation | [converse::take_turn](../../crates/pwr-orchestrator/src/converse.rs) has independent message history, decode/retry/compaction and terminal handling, while reusing adapters/catalog/executor. [CLI wrapper](../../crates/pwr-cli/src/main.rs) adds targeted pre/post checks. Characterized 2026-09-12 in `crates/pwr-cli/src/two_loops.rs`, which drives both loops from one script: it had no end-to-end fixture before that. | Same tools do not mean same agent. Improvements in one path may not reach another. |

Chat returns on ordinary narrative or `Complete`/`Decline`. Its `compact` discards older tool bodies and shortens requests; it does not use the scripted evidence ledger/plan context. The wrapper said “the repository's own checks passed after the change” when `comparison.new_failures.is_empty()`, a condition unchanged prior failures satisfy. Corrected 2026-09-12: `check_verdict` in the CLI separates every check green from a preserved baseline and names what is still failing, so the claim is specific to what was observed. The mismatch is gone at that one point; it was never a reason to require passing tests for every conversation answer, and the two loops still differ everywhere else.

Two divergences were pinned by fixture rather than described, and one is closed. **The conversation did not call `context::compose`**, whose own documentation says it "composes the opening prompt used for both an interactive run and an eval" and performs retrieval there "so section order, retrieval budget and compaction accounting cannot diverge by caller". Its callers were the eval path and the scripted `run`; the conversation opened with a bare system string and received no repository excerpts at all, so an H3 retrieval result measured through eval could not have reached the product. Closed 2026-09-12: `context::compose_turn` composes a conversation turn from the same sections through the same retrieval and eviction, and `compose_chat_turn` in the CLI routes the conversation through it against the room the history has left. Completed 2026-09-12: the conversation also receives the task-profile suffix, merged into its system message the way a run merges it, and a session ledger composed every turn from the files as they are on disk — the loop most exposed to compaction loss now has the deterministic record of what the discarded tool bodies said. **The same tool result reached the deployment in two shapes**, and the conversation's carried less detail: the run rendered a refusal as `{"denied": …}` and any other fault as `{"tool_failure": …, "failure_category": …}` inside `{"result": …, "status": …}`, while the conversation sent the bare result object on success and the string `refused: {problem}` on any failure — losing the difference between a policy decision and a broken tool, losing the category, and not being JSON. Closed 2026-09-12: `action_outcome` and `tool_result_message` in the orchestrator are the only place either is built. The declared difference that remains is `status`, which a run has and a conversation does not.

What is *not* divergent was also measured, and corrected an assumption: on a short exchange both loops send the same message roles and count, both apply the same edit from the same script, and both refuse a stale hash without changing the workspace.

## Disposition of important subsystems

Disposition is the primary migration decision; IMPLEMENTED means reachable code exists, not deployment-quality certification. All decisions are relative to the new thesis.

| Subsystem / source | Status and evidence | Decision and reason |
|---|---|---|
| Rust workspace / [Cargo.toml](../../Cargo.toml) | IMPLEMENTED, Rust 2024 / MSRV 1.88, 14 crates, Tokio/serde/SQLite, ratatui CLI. | **KEEP**: no evidence a language/runtime rewrite improves local inference capability. |
| Transport / [provider](../../crates/pwr-provider/src/lib.rs) | IMPLEMENTED `ModelProvider`, `InferenceBackend`, complete reply collection, typed failures and cancellation. | **KEEP**: prevents wire/protocol defects from contaminating agent policy; strengthen contracts without replacing transport. |
| Backend composition / [runtime](../../crates/pwr-runtime/src/lib.rs), Ollama (`pwr-ollama`, removed 2026-09-19), LM Studio (`pwr-lmstudio`, removed 2026-09-19) | IMPLEMENTED `RuntimeFactory`, lifecycle/discovery/context preparation and variant handling. | **KEEP**: already supports heterogeneous local backends; not an Ollama-only scaffold. |
| Hardware and lease / [hardware](../../crates/pwr-runtime/src/hardware.rs), orchestrator `ModelRuntimeLease` | IMPLEMENTED macOS/Linux/Windows probes and host-wide lease. Some evidence unavailable; hardware key does not fully capture accelerator changes. | **EVOLVE**: retain serial residency guard; extend identity/cost evidence before a scheduler. Hardware portability is not process isolation. |
| Domain/profile types / [domain](../../crates/pwr-domain/src/lib.rs) | IMPLEMENTED observations, provenance, budgets, deployment identity and canonical tools; `ModelProfile::select_for` uses digest → deployment → family → legacy tag. Requests still have raw JSON tools/string roles. | **EVOLVE**: preserve schemas/readers, strengthen typed content and explicit evidence versions rather than add duplicate types. |
| Compatibility / [compat](../../crates/pwr-compat/src/lib.rs) | IMPLEMENTED Generic/Qwen/Granite adapters and normalization diagnostics; `adapter_for` includes model-name fallback. | **EVOLVE**: preserve working codecs; replace inferred capability with observed contracts; H1/H6 justify adaptive representation. |
| Calibration / orchestrator `calibrate` | IMPLEMENTED v6 per-tier warmup/repetitions, granted context, occupancy/needle/complete-stream gates, pressure and rejection records. v5 sent the warm-up's prompt again for every counted sample, so on a backend with a prompt cache its first-token gate measured cached prefill (98 ms against about 89 s cold, measured 2026-09-13); v6 makes every sample's prompt differ from its first token. On LM Studio the ladder is asked for rung by rung, since some models serve a requested window and others do not, and collapses to the window in force only when none is served. | **EVOLVE**: retain operating-point measurement; cold samples are now guaranteed, and recording warm and cold latency separately remains to do, as does a task-like protocol. It is not useful-context or coding certification. |
| Profile policy / orchestrator `select_profile`, [strategies/models.json](../../strategies/models.json) | IMPLEMENTED highest stable context selection and historical fixed budgets; profiles retain blanket 262144-context requirements for some deployments. | **REPLACE**: use measured task/resource policy behind existing profile contract. Preserve legacy configurations for controlled baselines; large repo does not require whole-repo context. |
| Auto selection/certification / [selection](../../crates/pwr-cli/src/selection.rs), domain selector | IMPLEMENTED hard admission/scoring and scoped certification records. `CandidateFacts::into_candidate` sets `quality_score: None`; certification suite evidence is incomplete. | **EVOLVE**: keep explicit selection/explanations; do not imply optimal routing or quality ranking. H6 tests policy choice, not model-brand choice. |
| Scripted runtime / orchestrator loop | IMPLEMENTED state transitions, context, plan, approvals, retries, result execution and checks, concentrated in a large module. | **EVOLVE**: extract modules/ports without changing behavior until compatibility fixtures pass. |
| Interactive execution / `converse::take_turn` | IMPLEMENTED separate loop; no shared `RunState`, acceptance or recovery semantics. No same durable resume. | **REWRITE**: replace its decision loop with shared session-runtime calls while retaining terminal interaction. This is targeted replacement, not a project restart. |
| Planner / [plan.rs](../../crates/pwr-orchestrator/src/plan.rs) | IMPLEMENTED bounded subgoals, dependencies and optional check-backed progress; no robust general autonomous scheduler. | **EVOLVE**: validate graph and persist it exactly; keep plan-first optional and measure its benefit. |
| State/replay / orchestrator `RunState::replay`, [run_state.rs](../../crates/pwr-orchestrator/src/run_state.rs) | IMPLEMENTED event projection/effect tracking; replayed plan is a string vector rather than full graph/check state. | **EVOLVE**: explicit authoritative state and checkpoint reconciliation. Replay/reporting is not resuming execution. |
| Context / [context.rs](../../crates/pwr-orchestrator/src/context.rs), `compact_history` | IMPLEMENTED typed sections, pinned task, ledger/last exchange, budgeted excerpts. Approximate four-character token accounting and fixed reserve; required prefix may exceed budget. | **EVOLVE**: one context engine, full schema/modality accounting and rehydration; H2/H4 test evidence representation. |
| Duplicate chat compaction / `converse::compact` | IMPLEMENTED separate lossy policy, two-compactions-per-turn guard. | **REMOVE** after shared context equivalence tests: duplicate heuristics invalidate product/eval comparisons; compaction count is not a causal loop diagnosis. |
| Repository index / [repo](../../crates/pwr-repo/src/lib.rs) | IMPLEMENTED content-addressed index, SQLite metadata cache, lexical retrieval, shallow declarations/imports and heuristic neighbors. | Tool surface / [tools](../../crates/pwr-tools/src/lib.rs) | IMPLEMENTED reads/windows, search/tree, hash-guarded create/replace/multi-hunk patch, move/delete, Git status/diff, command/fetch, document extraction and services. | Commands/services / tools and [service.rs](../../crates/pwr-tools/src/service.rs) | IMPLEMENTED explicit argv, environment clearing, bounded pipes, process-group termination and supervised service readiness/lifecycle. No general interactive PTY computer-control surface. | **EVOLVE**: retain ownership/limits; add explicit process sessions only for demonstrated development needs. |
| Policy / `ToolPolicy`, `sandbox_profile` | IMPLEMENTED macOS seatbelt, path/protected-file checks, approvals, read restrictions, network/local-service distinctions and audited outcomes. Chat starts with `all_approvals()` and `Preferred`. | **EVOLVE**: make autonomy/scopes visible and extensible to authorized host resources; never infer broad permissions from a prompt. |
| Results/diagnostics / `bounded_result`, tools output, [verify](../../crates/pwr-verify/src/lib.rs) | IMPLEMENTED serialization bounds, head/tail capture, hashes, shallow located diagnostics and failure classes. Raw discarded command bytes are not necessarily stored. | **EVOLVE**: structured views plus real retrievable artifacts; H4 tests inference savings without missing evidence. |
| Acceptance/recovery / verifier `discover_checks`, `compare`, `classify_with_reproduction` | IMPLEMENTED declared/CI-text/15-marker checks, baseline exceptions, web assets, reproduction and bounded recovery in scripted path. Repeated-refusal and no-progress detection were scripted-only and are now shared: `repetition::RefusalStreak` and `stall` are the one definition of each, and the conversation names, stops and audits both as the run does. A conversation turn now has a soft action budget that stops to check in, and bounds backend faults separately from deployment faults: any provider error other than a truncated or unparseable reply used to end the turn with `Err`, which returns no messages to the console while the edits stay on disk — a dropped connection after three edits left the files changed and the conversation with no record of it. Measured-tier context recovery is shared as of 2026-09-12: the chat passes its calibration profile's admitted stable points into the turn, and a prompt the backend refuses is retried at a measured window before compaction is spent on it. The console's own stricter filter is used rather than the scripted loop's, excluding tiers that showed memory pressure, so a turn in trouble cannot fall to a tier preparation already refused. Where a backend cannot be calibrated there is no ladder to descend and compaction is the whole answer. Plan state remains scripted-only by decision rather than by omission: see the roadmap's R1 entry and the research contract's fourth open question, which preregisters the comparison that would change it and rules out a plan-first default until then. CI parsing is heuristic; web checks do not render. | **EVOLVE**: keep objective checks; separate delivery/acceptance and unify path-specific outcomes. A model-authored passing test is not independent evidence. |
| PDF import / [document.rs](../../crates/pwr-tools/src/document.rs) | IMPLEMENTED narrow text/URI extraction with `flate2`, explicit unsupported cases; not general OCR/layout or vision. | **RESEARCH FURTHER**: compare a maintained parser or external scoped extractor on a real corpus before investing further in bespoke PDF internals. |
| Store / [store](../../crates/pwr-store/src/lib.rs) | IMPLEMENTED SQLite events, hashes, global/per-run links and verification API, session summaries. No complete artifact retention/migration/resume contract. | **EVOLVE**: keep persistence; add transactional checkpoints/schema validation. Hash chains are inspectability, not tamper-proof storage against a malicious owner. |
| Observability / [observe](../../crates/pwr-observe/src/lib.rs), [diagnose](../../crates/pwr-observe/src/diagnose.rs) | IMPLEMENTED JSONL/replay and deterministic known-pathology detectors with real trace fixtures. | **KEEP**: useful zero-inference failure analysis; new failures still require investigation and detectors require validated definitions. |
| Evaluation / [eval](../../crates/pwr-eval/src/lib.rs) | IMPLEMENTED corpus checks, reports/provenance, completed traces and paired costs. `compare` retains provider-failure exclusion and its three-field pair key; `compare_strict` beside it (added 2026-09-12) rejects duplicate trials and undeclared condition differences and counts every assigned trial. Campaign durability and a persisted trial manifest remain absent. | **EVOLVE**: the comparator half of the strict trial contract exists and is fixture-backed; persistence and campaign export are the remainder. Existing corpora remain regression/development data. |
| UI / [CLI main](../../crates/pwr-cli/src/main.rs) | IMPLEMENTED terminal settings/conversation/attachments/cancellation/reporting; substantial runtime decisions live in CLI. No separate backend API or web UI. The console offered four commands against the CLI's twelve subcommands and now offers eight: `/doctor`, `/diagnose`, `/verify` and `/report` were added 2026-09-12, the first two because the conversation had begun telling operators to check the backend and writing loop and no-progress events with no way to see either from inside it. Each summarises rather than printing the command's JSON. `repo` and `models` remain command-line only, and neither is promised by anything the conversation says. | **EVOLVE**: retain useful interaction; move decisions to runtime and render meaningful events. |
| Vision, semantic memory, MCP/plugins, browser/desktop, worker scheduling | PLANNED or RESEARCHING; no complete model/tool/runtime path. | **RESEARCH FURTHER**: capability-based interfaces allow later experiments; do not call them implemented because domain metadata mentions modalities. |

## Existing tests and maturity

The suite includes provider stream/cancellation fixtures, profile invariants, sandbox adversarial cases, filesystem/Git/patch/service checks, compaction and task-retention fixtures, planning/loop/state tests, corpus soundness and real-log diagnostic tests. CI on macOS runs formatting, clippy, workspace tests and the generated milestone check. This is substantive engineering infrastructure; a green offline suite would still not prove autonomous model capability.

The development corpus and `experiments/` retain protocols, reports and failed hypotheses. `pwr-tests/` contains manual application campaigns and interrupted runs; these are heterogeneous investigations, not interchangeable controlled trials. `.pwr/` and generated output are runtime artifacts, not canonical requirements. No live model inventory was refreshed during this audit; old model tags are observations from their dates.

## Historical assumptions rejected

- Maximum advertised context is always the best operating point; 262K is required for large repositories.
- A valid short tool probe predicts sustained coding competence.
- Every useful output must end in green repository tests, including prose/diagnosis.
- A chat sharing tools shares the benchmarked runtime.
- Parameter count, tag or a single task's cost predicts the right policy everywhere.
- Another agent implies faster execution on a memory-constrained local GPU.
- Hand-written parsers and a complete custom framework are necessary to make the harness valuable.

Some assumptions are not specifically “frontier” assumptions at all: malformed wire history and discarded evidence break any model. Others—free-form plan integration, faithful summary generation and tool-choice competence over a large catalog—depend on capabilities that must be measured rather than presumed in a local deployment.

## Audit limits

This is an implementation/design audit, not a security certification or fresh performance benchmark. Source was read across manifests, adapters, runtime, tools, repository, state, UI, verification, persistence, tests and experiment documentation; Git history was used to explain the split loop and earlier measurement-driven changes. User changes already present in source/tests/Cargo.lock were treated as current evidence and left intact. The documentation change intentionally makes no source refactor.
